# 采集后的图文判断与知识库交接

本 Skill 提供采集、原图和 OCR；Jev 判读与 Dify 适配是独立下游。本节定义交接要求，不代表任意项目已接通这些服务。

## 来源先于标签

读取经过 SHA/bytes 校验的消息和图片回执。区分完整区间与页限抽样，并保留会话列表触顶、未采上下文、未转译消息、媒体未就绪等未知状态。空结果、缺失 OCR 和局部完成不能变成“没有记录/图片无信息/全店完整”。

下游需要结构化证据单元：`id/role/kind/text`，role 来自已验证的消息发送者，kind 区分消息、图片和 OCR。角色不能从正文中的“客户原话”“客服原话”字样反推；客户原文可以包含这些字样。公开 opaque ID 与真实消息 ID 的映射留在本地私有文件。展示转义只解码一次，再按纯文本渲染。

源内容指纹与 Dify 最终文档指纹分开记录。源指纹覆盖顺序、角色、内容及需复核标记；加入模型标签后生成新的文档指纹，不覆盖原始消息或原模型结果。接口来源使用自己的稳定命名空间，不伪造 DOCX 案例号。

## Jev 的工作边界

将图文分类拆成图片内容和会话判断两层。图片类别可在处理后图片、问题定义、模型版本一致时复用；客户意图、付款、退款、投诉和是否解决依赖会话上下文，不能仅按图片 SHA 复用。

图片先做本地 OCR、敏感信息检查和必要处理，保留原图与处理后图片的映射。外发只使用已核对的 PNG/JPEG 和必要脱敏文本。实际请求指纹包括送出的图片字节、文本、角色、上下文、问题与固定模型版本。别名相同不代表模型未变化。

Jev 适合固定分类、证据充分性等小判断；其置信度不等于正确率。原话、OCR、模型判断、独立复核、人工审核分别归因。信息不足保持未知，不用宣传图证明客户付款，不用他人评价证明当前客户投诉。图片能力和调用格式以[官方图片文档](https://docs.typesafe.ai/images)为准。

普通索引同步、已审定标签复用和常规检索问答不触发重新分类。限流、认证、额度或网络故障保留完成结果并停止相应阶段；不换模型冒充 Jev、不自动重复扣费请求。

## 复核与知识库

先冻结小样及人工基准，再比较仅 OCR 与图文判断。独立审查先看原始证据，再比较模型结果；复盘报告不能代替每批入库审核。未决项留在本地，机器审核不能标成人工审定。

接入既有 Dify 时，单独核验来源适配、文档/元数据同步、检索命中、引用定位及网站实际回答。上传文档不代表所有聊天分支都会检索它。历史案例始终标记为历史资料，不能变成现行政策或本单事实；缺失数量不明时省略，不填零。

## 中断与并发

消息、下载、OCR和判断分别推进。恢复前核验进程 PID、命令及创建信息，再检查已保存 CAS 结果的 SHA/profile/来源；可登记的结果先登记。确认没有有效结果且原进程已结束，才明确释放该领取记录。保留原失败/领取证据，不批量清空。

浏览器 runtime、session 和 target 是一次运行的记录，不是长期可复用的登录状态。退休登记必须绑定原 runtime 全文件 SHA，旧 session 名继续保留；不因观察超时就认定进程退出，也不为监测重启健康进程。

吞吐以真实有效完成量衡量，合成测试或单次成功不证明持续并发稳定。Windows 的长路径问题用短输出/测试目录定位，不能通过移除路径越界校验解决。
